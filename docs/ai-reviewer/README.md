# מערכת ביקורת קוד עצמאית מבוססת בינה מלאכותית

מערכת זו מיישמת ביקורת עמיתים אוטומטית, קפדנית ובלתי תלויה עבור בקשות משיכה בגיטהאב.
הסוכן הבודק פועל בתהליך נפרד לחלוטין, ללא גישה לקונטקסט או לשיחות של הסוכן המפתח.
המערכת נבדקה ומאומתת לפעולה רציפה בצינור הבנייה.

---

## עקרונות הארכיטקטורה ומודל האבטחה

המערכת בנויה על מודל שני שלבים מבודד:

1. **שלב הבדיקות הלא-מהימן**:
   * רץ בסביבה נטולת הרשאות לחלוטין (קריאה בלבד).
   * נטול גישה לסודות, למפתחות או להרשאות כתיבה במאגר.
   * מריץ את בדיקות הקוד והניתוח הסטטי ומפיק קובץ תוצאות פסיבי ומוגבל בגודלו (עד 100 קילובייט).

2. **שלב הביקורת המהימן**:
   * מופעל רק בסביבה מאובטחת בעלת גישה למפתחות.
   * אינו מריץ קוד או סקריפטים שמקורם בבקשת המשיכה בשום מצב.
   * שולף ישירות את השינויים מול מזהה ההתחייבות המדויק.
   * מבודד את כל תוכן הקבצים, התיאורים והודעות השגיאה כדי למנוע הזרקת הוראות זדוניות.
   * מפרסם ביקורת מובנית והערות ישירות בשורות הקוד.
   * עוקב אחר ממצאים שנפתרו או נותרו פתוחים בין דחיפות חוזרות.

---

## מדריך העתקה ושימוש במאגרים אחרים

כדי להטמיע את המערכת בכל מאגר חדש, יש לבצע 4 שלבים פשוטים:

### 1. העתקת קובצי המנוע
יש להעתיק את התיקייה `scripts/ai-reviewer/` אל המאגר החדש:
* `config.js` – טעינת הגדרות.
* `prompts.js` – הוראות מערכת ומנגנוני הגנה מפני הזרקת הוראות.
* `validator.js` – אימות תוצרים והגבלת גדלים.
* `github.js` – תקשורת מול גיטהאב ומעקב גרסאות.
* `reviewer.js` – תקשורת ישירה מול ממשק הבינה המלאכותית.
* `cli.js` – ממשק הרצה מרכזי.

### 2. יצירת קובץ הגדרות מקומי
יש להניח בתיקיית השורש קובץ בשם `.ai-reviewer.json` המותאם למאגר:

```json
{
  "projectLanguage": "typescript",
  "technologyStack": "Node.js, React",
  "architectureDocs": ["README.md", "docs/architecture.md"],
  "codingStandards": ["CONTRIBUTING.md"],
  "securityRequirements": [
    "Zero-trust input boundaries",
    "Sanitize all inputs"
  ],
  "reviewFocusAreas": [
    "Functional correctness",
    "Security vulnerabilities",
    "Error handling and edge cases"
  ],
  "severityThresholds": {
    "blocking": ["CRITICAL", "HIGH"],
    "warning": ["MEDIUM"],
    "advisory": ["LOW", "INFO"]
  },
  "testCommands": ["npm test"],
  "excludedPaths": [
    "node_modules/**",
    "dist/**",
    "package-lock.json"
  ]
}
```

### 3. העתקת זרימת העבודה
יש להעתיק את הקובץ `.github/workflows/ai-code-reviewer.yml` אל תיקיית `.github/workflows/` במאגר.

### 4. הגדרת המפתח בגיטהאב
בהגדרות המאגר בגיטהאב, תחת סודות הפעולות:
* שם הסוד: `GEMINI_API_KEY` (או `ANTIGRAVITY_API_KEY`).
* ערך: מפתח הגישה של גוגל.

## 14 ממדי הביקורת המחייבים

הסוכן הבודק סוקר באופן עצמאי ומחמיר:
1. נכונות פונקציונלית.
2. עמידה בדרישות המפרט.
3. פגיעויות אבטחה.
4. הזדהות והרשאות.
5. תקינות ועקביות נתונים.
6. מקביליות ומרוצי תהליכים.
7. טיפול בשגיאות והתאוששות.
8. מקרי קצה ותנאי גבול.
9. ביצועים ויכולת גדילה.
10. עקביות ארכיטקטונית.
11. תחזוקתיות וקריאות.
12. כיסוי בדיקות ומקרי מבחן חסרים.
13. תאימות לאחור.
14. סיכוני פריסה ותצורה.

## מעקב שינויים ובדיקות חוזרות

בכל דחיפת שינוי חדשה לאותה בקשת משיכה:
1. מופעל סשן ביקורת חדש לחלוטין.
2. המערכת קוראת את הממצאים שפורסמו בגרסה הקודמת.
3. ממצאים שתוקנו מסומנים כירוקים ונפתרו.
4. ממצאים שעדיין קיימים מסומנים כאזהרה וממשיכים להופיע.
5. פגמים חדשים שנוצרו מסומנים כחדשים ומקבלים דגש מיוחד.
