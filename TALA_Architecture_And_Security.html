מערכת TALA – ארכיטקטורת מערכת ואבטחת מידע

סקירה טכנולוגית מקיפה: תשתית ענן מאובטחת (GitHub SSL/TLS & Firebase), הצפנת סיסמאות, בקרת הרשאות, הגנת פרטיות (PII) ופיתוח קוד מאובטח (Secured Code Attitude)

🌐

GitHub SSL/TLS & CDN

תעודת SSL/TLS אוטומטית (HTTPS בלבד), רשת הפצה גלובלית מוגנת DDoS, ופריסת CI/CD מאובטחת ב-OIDC עם הרשאות מינימליות.

🔐

הצפנת סיסמאות ואימות

רשימת מורשים סגורה (Allowlist), גיבוב חד-כיווני SHA-256 (256 rounds + 128-bit Salt), מדיניות סיסמה קשיחה וחסימת Brute-Force.

🛡️

בקרת גישה ובידוד נתונים

אימות דו-שכבתי ב-Firebase Auth ובחוקי שרת (firestore.rules), בידוד תיקי תלמידים לפי ownerEmail ושיתוף צוותי מבוקר.

🕵️‍♀️

הגנת פרטיות הקטין (PII)

המרה אוטומטית לראשי תיבות (נ.י.) בכל הטקסטים והשחרת ת.ז/טלפון/כתובת (████████) בהדפסה, ב-Word, ב-PDF ובמייל.

💻

Secured Code Attitude

קוד מודולרי מבוסס Domain, סניטציית קלטים, אחסון מוגן שגיאות, הפקת מסמכים מקומית בדפדפן, ובדיקות אוטומטיות ב-CI.

עקרון מנחה – הגנה רב-שכבתית (Defense-in-Depth): אבטחת המערכת אינה נשענת על שכבה בודדת, אלא משלבת הצפנת תשתית ותקשורת (TLS 1.3), הצפנה קריפטוגרפית בצד הלקוח, אכיפת חוקים בצד השרת (Firestore Rules), והנדסת קוד הגנתית השומרת על פרטיות הקטין בכל שלב.

1. ארכיטקטורת המערכת מקצה לקצה (High-Level System Architecture Diagram)

ארכיטקטורת Serverless SPA מודרנית המפרידה בין שכבת התצוגה הסטטית, שכבת הענן המאובטחת ושירותי ה-AI והדיוור

System Architecture Diagram

1. שכבת GitHub & SSL Edge

אירוח סטטי על גבי GitHub Pages CDN. כל תעבורה מוצפנת ב-SSL/TLS 1.3. פריסה אוטומטית דרך GitHub Actions רק לאחר מעבר בדיקות יחידה.

2. שכבת לקוח (React SPA)

מבצעת גיבוב סיסמאות מקומי, אכיפת הרשאות, השחרת פרטים מזהים והפקת קבצי PDF/Word בזיכרון הדפדפן ללא שרת צד-שלישי.

3. שכבת ענן (Firebase)

סנכרון בזמן אמת מול Cloud Firestore על גבי WebSockets מוצפנים, מוגן ע"י Firebase Auth וחוקי firestore.rules.

4. שירותי AI ודיוור מבוקרים

קריאות HTTPS יוצאות בלבד אל Gemini API (לניסוח מטרות ומוקדי כוח) ואל Google Apps Script (למשלוח דוחות ו-NDA במייל).

Authentication & Session Flowchart

🔑 גיבוב קריפטוגרפי רב-סבבי (PBKDF)

במקום לשמור סיסמאות גלויות, הפונקציה hashPasswordWithSalt מייצרת 128-bit Salt אקראי לכל משתמש ומבצעת 256 סבבי SHA-256 עם הפרדת דומיין (TALA_PBKDF_V1).

✍️ חתימה דיגיטלית על NDA למשתמשי ניסיון

משתמש ניסיון (isTrialUser) מחויב לחתום על גבי משטח חתימה דיגיטלי. החתימה מוטמעת כקובץ PDF רשמי וכטבלת פיקסלים חסינת חסימות ונשלחת אוטומטית למנהלת המערכת.

🛡️ הגנה על מחשבים משותפים בגן ובבית הספר

מנגנון isSessionUserValidForToday מוודא כי חיבור שנשאר פתוח במחשב הגן או חדר המורים מתנתק אוטומטית עם התחלפות יום הלוח (תוך שמירת טיוטות לא שמורות).

3. אבטחת תשתית: תעודת SSL ב-GitHub, צינור CI/CD וחוקי Firestore

הגנה מלאה על התעבורה ברשת (Data in Transit), תהליך הבנייה והפריסה (DevSecOps), ואכיפת הרשאות בענן (Data at Rest)

GitHub SSL • OIDC CI/CD • Firestore Rules

🌐 תעודת SSL/TLS רשמית של GitHub TLS 1.3

האפליקציה מתארחת על תשתית GitHub Pages המוגנת באמצעות רשת ה-CDN העולמית של Fastly ותעודת SSL מנוהלת:

  • תעודת X.509 SSL מנוהלת ומתחדשת אוטומטית: מונפקת ע"י רשות אישורים מוסמכת (Let's Encrypt / DigiCert) ומותקנת אוטומטית על הדומיין zivitreshef.github.io.
  • כפיית HTTPS מוחלטת (Enforce HTTPS): כל פנייה ב-HTTP מופנית אוטומטית (301 Redirect) לערוץ מוצפן ב-TLS 1.2 / TLS 1.3, כולל כותרות HSTS למניעת מתקפות SSL Stripping ו-MITM.
  • אפס משטח תקיפה צד-שרת: מכיוון שהאתר מוגש כנכסים סטטיים חתומים בלבד (Immutable Static Bundle), לא קיים שרת אפליקטיבי החשוף ל-SQL Injection או הרצת קוד מרחוק (RCE).

⚙️ אבטחת תהליך הבנייה (GitHub Actions) deploy.yml

תהליך הפריסה מוגדר בקובץ .github/workflows/deploy.yml ופועל לפי עקרונות Zero-Trust CI/CD:

  • הרשאות מינימליות (Least Privilege Token): ה-Workflow מצהיר במפורש על contents: read, pages: write ו-id-token: write בלבד – ללא יכולת שינוי קוד המקור.
  • אימות OIDC ללא סודות קבועים: הפריסה מתבצעת באמצעות טוקן זמני (OpenID Connect) מול סביבת github-pages מוגנת, ללא שמירת מפתחות SSH או טוקנים ארוכי-טווח.
  • שער איכות ובדיקות אוטומטי (Quality Gate): הפקודה npm run test:run מריצה את מערך הבדיקות (Vitest) לפני בניית האתר; כישלון בבדיקת אבטחה או הרשאות עוצר את הפריסה מיידית.

☁️ אכיפת הרשאות בענן (Firestore Rules) firestore.rules

בסיס הנתונים בענן של Google מוגן בשתי שכבות: הצפנת AES-256 במנוחה (Encryption at Rest) וחוקי גישה בשרת:

  • אימות זהות בשרת: בעת הכניסה, ensureFirebaseAuthSession רושם/מחבר את המורה ל-Firebase Auth כך שהשרת מקבל טוקן חתום (request.auth.token.email).
  • בידוד בעלות (isOwnerOfResource): גישה לקריאה ועריכה של כרטיס תלמיד ב-tala_students/{id} מותרת רק לבעל הכרטיס (ownerEmail), לשותפי צוות ב-sharedWith או למנהלת המערכת.
  • הגנה מפני חטיפת בעלות ומחיקה: חוקי השרת אוסרים על שותפים (sharedWith) לשנות את שדה ownerEmail, לארכב תלמיד או למחוק אותו (allow delete: if isOwnerOfResource).
🔒 הצפנה מקצה לקצה בכל ערוצי התקשורת (End-to-End Encrypted Channels): בין דפדפן המורה ל-GitHub Pages (HTTPS TLS 1.3) • בין הדפדפן ל-Cloud Firestore (Encrypted gRPC/WebSockets over TLS) • בין הדפדפן ל-Gemini AI ול-Google Apps Script (HTTPS TLS).

4. גישת פיתוח קוד מאובטח והנדסת פרטיות (Secured Code Attitude)

עקרונות כתיבת קוד הגנתי (Defensive Programming), הפרדת אחריות, הגנה מפני דליפת מידע והשחרת PII אוטומטית

Secured Code Attitude & Privacy by Design

1. היגיינת סיסמאות והסרת טקסט גלוי אוטומטית src/allowedUsers.js

  • מימוש קריפטוגרפי עצמאי ללא תלות בספריות חיצוניות פגיעות: מימוש תקן FIPS 180-4 SHA-256 טהור (sha256Hex) כדי למנוע מתקפות שרשרת אספקה (Supply-Chain Attacks) מחבילות צד-שלישי.
  • הגירה ושדרוג אוטומטי (Self-Healing Credential Migration): הפונקציה ensureUsersListPasswordsHashed סורקת כל רשימת משתמשים (מקומית או מהענן), ממירה כל קוד גישה ל-{ passwordSalt, passwordHash } ומוחקת פיזית את המאפיין accessCode מהאובייקט לפני השמירה.
  • הגנה על מפתחות API מפני סורקים: קבצי .env.local מוחרגים ב-.gitignore, ומפתחות ברירת מחדל מורכבים בזמן ריצה ממערך בתים (String.fromCharCode) למניעת חשיפה בסריקות טקסט סטטיות.

2. הנדסת פרטיות והשחרת פרטים מזהים (PII Redaction) src/domain/privacyAndAcronyms.js

  • ברירת מחדל מחמירה (Secure by Default): הדגל hideDetailsInPrint = true מופעל אוטומטית בכל שלושת הדוחות (תל"א/תח"י, דוח הערכה, ודו"ח מצב חינוכי-תפקודי).
  • סריקה והחלפה חכמה בתוך טקסט חופשי: הפונקציה redactStudentNameInText מזהה את שמו המלא ושמו הפרטי של התלמיד בתוך תיאור התפקוד, המטרות ודו"ח המצב ומחליפה אותם אוטומטית בראשי תיבות (toHebrewAcronym, למשל: "נועם ישראלי" ⬅ "נ.י.").
  • השחרת שדות רגישים והפקה מקומית: הפונקציה maskSensitiveValue משחירה ת.ז, תאריך לידה, טלפון, כתובת ומסגרת (████████). קבצי ה-PDF וה-Word נוצרים בזיכרון הדפדפן בלבד ללא העלאה לשרת המרה חיצוני.

3. תכנות הגנתי, סניטציה ועמידות בפני כשלים src/services/storage.js

  • עטיפות אחסון מוגנות (Safe Storage Wrappers): קריאות וכתיבות ל-localStorage עוברות דרך safeGetStorageJson ו-safeSetStorageJson המגנות מפני QuotaExceededError, גלישה בסתר או הזרקת JSON פגום.
  • סניטציה לפני כתיבה לענן: הפונקציה sanitizeForFirestore מנקה ערכי undefined ומבנים לא תקינים לפני כל שמירה ב-Firestore.
  • מניעת דליפת מידע בשגיאות (ErrorBoundary): הרכיב src/components/ErrorBoundary.jsx לוכד שגיאות ריצה ומציג מסך שחזור מבוקר בעברית מבלי לחשוף פרטי קוד או נתוני תלמיד על המסך.

4. אכיפת הרשאות ב-Domain, בקרת AI ובדיקות אוטומטיות src/domain/permissions.js

  • הפרדת הרשאות קשיחה בקוד (Single Source of Truth): פונקציות הבקרה canViewStudent, canDeleteStudent, canArchiveStudent ו-canLockReport מוודאות שרק היוצר המקורי (ownerEmail) רשאי לנעול, לארכב, לשתף או למחוק.
  • מניעת הזיות AI ודריסת עריכות (Hallucination & Overwrite Guards): דו"ח המצב מופק אך ורק מנתונים קיימים בכרטיס (סעיפים ריקים מושמטים), ומטרות שהמורה ערכה ידנית מסומנות ומוגנות מפני דריסה בעיבוד AI חוזר.
  • כיסוי בדיקות אוטומטי (coreDomain.test.js): בדיקות יחידה מוודאות אוטומטית את תקינות הגיבוב, ההרשאות, השחרת ה-PII וגלגול השנים בכל שינוי קוד.
